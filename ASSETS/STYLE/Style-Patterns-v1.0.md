Version: 1.0

Status: Active

Owner: HSDD

# Purpose

This document records reusable patterns discovered through Style Engineering.

Patterns represent recurring structures that can be applied across communication, design, operations, documentation, and decision-making.

A pattern becomes an asset when it can be reused consistently.

---

# Pattern Structure

Each pattern follows the same format.

```text
Pattern Name

Observation
↓
Principle
↓
Application
```

---

# Pattern-001

Name

Signal Over Noise

---

Observation

Most information contains unnecessary complexity.

The useful signal is often hidden behind excessive detail.

---

Principle

Reduce information until only the meaningful signal remains.

---

Application

- Writing
- Communication
- Documentation
- Meetings
- Strategy

---

Expected Outcome

Higher clarity.

Lower cognitive load.

Better decision making.

---

# Pattern-002

Name

Structure Before Scale

---

Observation

People often attempt to scale before a structure exists.

This creates instability.

---

Principle

Build a repeatable structure first.

Expand only after the structure is proven.

---

Application

- Business systems
- Documentation
- Projects
- Teams
- Repositories

---

Expected Outcome

Improved maintainability.

Reduced complexity.

---

# Pattern-003

Name

Asset Thinking

---

Observation

Most work disappears after completion.

Only documented work becomes reusable.

---

Principle

Convert outputs into assets.

---

Application

- Research
- Notes
- Frameworks
- Workflows
- AI prompts

---

Expected Outcome

Long-term value accumulation.

# Pattern-004

Name

---

Application

Expected Outcome

# Pattern Library Expansion Rule

A new pattern should only be added if:

- It has appeared multiple times
- It can be explained clearly
- It can be reused
- It creates measurable value

Patterns should emerge from observation.

Patterns should not be invented without evidence.

# Objective

The objective of patterns is not categorization.

The objective is transferability.

A pattern should allow knowledge to move from one context to another without losing usefulness.
